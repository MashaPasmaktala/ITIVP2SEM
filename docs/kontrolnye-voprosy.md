# Лабораторная работа №6 — ответы на контрольные вопросы

Примеры взяты из этого проекта («Попутчик», сервис совместных поездок).

---

### 1. Чем MongoDB отличается от реляционных СУБД (PostgreSQL, MySQL)? Минимум 4 отличия.
1. **Модель данных.** В MongoDB данные хранятся в документах (BSON, похоже на JSON) внутри коллекций, а не в строках таблиц.
2. **Схема.** MongoDB не требует жёсткой схемы: документы в одной коллекции могут иметь разные поля. В SQL структура задаётся `CREATE TABLE` и меняется миграциями. В нашем проекте схему задаёт Mongoose на уровне приложения.
3. **Вложенность вместо JOIN.** Связанные данные можно хранить внутри документа: остановки и отзывы лежат прямо в поездке. В PostgreSQL для этого нужны отдельные таблицы и `JOIN`.
4. **Язык запросов.** Вместо SQL используются методы и JSON-фильтры: `find({ price: { $lte: 30 } })`, aggregation pipeline.
5. **Масштабирование.** MongoDB изначально рассчитана на горизонтальное масштабирование (шардинг). Реляционные СУБД традиционно масштабируют вертикально.
6. **Транзакции и целостность.** В SQL есть внешние ключи (`FOREIGN KEY`, `ON DELETE CASCADE`). В MongoDB ссылочную целостность обеспечивает приложение: у нас каскадное удаление сделано в `pre('findOneAndDelete')`.

### 2. Что такое ObjectId? Как он генерируется и для чего используется?
`ObjectId` — 12-байтовый уникальный идентификатор, значение по умолчанию для поля `_id` у каждого документа. Его генерирует драйвер на клиенте, без обращения к серверу. Состав:
- 4 байта — время создания (Unix-секунды);
- 5 байт — случайное значение, уникальное для процесса;
- 3 байта — счётчик.

Используется как первичный ключ и для ссылок между документами. Например, `Trip.driver` — это `ObjectId` пользователя. Из ObjectId можно получить дату создания: `id.getTimestamp()`. Выглядит так: `6af9f5cdc572a2c721a004b1`.

### 3. Как выполнить поиск документов по вложенному полю (например, `profile.city` равен "Минск")?
Через «точечную нотацию» в кавычках:
```js
User.find({ 'profile.city': 'Минск' });
```
В нашем проекте по этому полю ещё и создан индекс: `userSchema.index({ 'profile.city': 1 })` (`models/User.js`).

### 4. Какие типы данных поддерживает BSON? Не менее 5.
`String`, `Int32` / `Int64` / `Double` / `Decimal128` (числа), `Boolean`, `Date`, `ObjectId`, `Array`, `Object` (вложенный документ), `Null`, `Binary` (двоичные данные), `RegExp`, `Timestamp`.

В схеме `Trip` используются `String` (from, to), `Number` (price), `Date` (departureAt), `Boolean` (options.smoking), `ObjectId` (driver), `Array` (tags, stops, reviews), `Object` (options).

### 5. Что такое агрегация (aggregation pipeline)? Пример минимум из двух стадий.
Aggregation pipeline — это конвейер стадий обработки: документы по очереди проходят через стадии (`$match`, `$group`, `$sort`, `$lookup`, `$unwind`, `$project`…), и каждая стадия преобразует результат предыдущей. Это аналог `WHERE` + `GROUP BY` + `JOIN` + `ORDER BY` в SQL.

Пример из проекта — средний рейтинг водителя (`models/Trip.js`, `driverRating`):
```js
Trip.aggregate([
  { $match: { driver: driverId } },          // 1. поездки этого водителя
  { $unwind: '$reviews' },                    // 2. «развернуть» массив отзывов
  { $group: {                                 // 3. сгруппировать и посчитать
      _id: '$driver',
      avgRating: { $avg: '$reviews.rating' },
      reviewsCount: { $sum: 1 },
  } },
]);
```
Ещё пример — топ направлений в `routes/admin.js`: `$match → $lookup → $unwind → $group → $sort → $limit → $project`.

### 6. Как в Mongoose определить вложенный документ (subdocument) без отдельной коллекции? Пример из проекта.
Нужно описать отдельную схему и использовать её как тип поля. Для одиночного объекта поле задаётся схемой, для списка — массивом схем:
```js
const carSchema = new Schema({
  brand: { type: String, required: true },
  model: { type: String, required: true },
  year: Number,
}, { _id: false });

const stopSchema = new Schema({ city: { type: String, required: true }, time: Date });

const userSchema = new Schema({ car: carSchema });            // одиночный вложенный документ
const tripSchema = new Schema({ stops: [stopSchema] });       // массив вложенных документов
```
Отдельная коллекция при этом не создаётся: данные хранятся внутри документа `users` или `trips`.

### 7. Как обновить элемент внутри массива (например, увеличить количество товара в корзине)?
Через **позиционный оператор `$`**: фильтр находит нужный элемент массива, а `$` в пути обновления указывает именно на него. Из проекта (`PATCH /trips/:id/reviews/:reviewId`):
```js
Trip.findOneAndUpdate(
  { _id: tripId, 'reviews._id': reviewId },
  { $set: { 'reviews.$.rating': 4, 'reviews.$.comment': 'Хорошо' } },
  { returnDocument: 'after' }
);
```
Увеличить количество элемента в «корзине»:
```js
Cart.updateOne(
  { _id: cartId, 'items.product': productId },
  { $inc: { 'items.$.quantity': 1 } }
);
```
Ещё есть `$[]` (все элементы) и `$[elem]` с `arrayFilters` (элементы по условию).

### 8. В чём преимущество вложенных документов перед отдельными коллекциями? В чём недостаток?
**Плюсы:**
- одно чтение вместо нескольких запросов или `JOIN`: поездка с остановками и отзывами приходит одним документом;
- атомарность: изменение одного документа всегда атомарно;
- данные лежат так же, как используются в коде и на фронтенде.

**Минусы:**
- размер документа ограничен 16 МБ, поэтому неограниченно растущие списки вкладывать нельзя;
- дублирование данных: мы храним копию `authorName` в отзыве, и при смене имени она устареет;
- сложно искать и обновлять вложенные данные «сами по себе», например все отзывы пользователя (нужна агрегация с `$unwind`);
- при частом изменении большого массива перезаписывается весь документ.

Поэтому брони у нас вынесены в отдельную коллекцию `bookings`: они нужны и со стороны пассажира, и со стороны поездки, и часто меняются.

### 9. Как в Mongoose создать индекс для поля (например, для ускорения поиска по email)?
Есть три способа:
```js
email: { type: String, unique: true }        // уникальный индекс (models/User.js)
role:  { type: String, index: true }          // обычный индекс
tripSchema.index({ from: 1, to: 1, departureAt: 1 });  // составной индекс (models/Trip.js)
```
Mongoose создаёт индексы при старте приложения (`autoIndex`) или вызовом `Model.syncIndexes()` (так сделано в `seed/seed.js`). Посмотреть индексы можно в Compass, на вкладке **Indexes**.

### 10. Что такое populate в Mongoose и для чего он нужен?
`populate` подставляет вместо `ObjectId` из поля с `ref` сам связанный документ из другой коллекции. Это аналог `JOIN`, только выполняется дополнительным запросом.
```js
// В схеме: driver: { type: ObjectId, ref: 'User' }
Trip.findById(id).populate('driver', 'email profile car');
// → trip.driver = { _id, email, profile: {...}, car: {...} } вместо простого ObjectId
```
Вложенный populate в «Моих бронях» (`routes/trips.js`): бронь → поездка → водитель:
```js
Booking.find({ user: userId }).populate({ path: 'trip', populate: { path: 'driver' } });
```

### 11. Как выполнить поиск с условием «поле-массив содержит значение» (например, tags содержит "важный")?
Достаточно обычного равенства: MongoDB сама проверяет элементы массива.
```js
Trip.find({ tags: 'комфорт' });                        // содержит значение
Trip.find({ tags: { $in: ['комфорт', 'утро'] } });     // содержит хотя бы одно
Trip.find({ tags: { $all: ['комфорт', 'утро'] } });    // содержит все
Trip.find({ reviews: { $elemMatch: { rating: { $gte: 4 }, author: id } } }); // элемент по нескольким условиям
```
В API: `GET /trips?tag=комфорт`.

### 12. Как удалить документ по id и вернуть удалённый документ в ответе?
`findByIdAndDelete` возвращает удалённый документ (или `null`, если его не было):
```js
router.delete('/:id', async (req, res) => {
  const deleted = await Trip.findByIdAndDelete(req.params.id);
  if (!deleted) return res.status(404).json({ error: 'Поездка не найдена' });
  res.json({ message: 'Поездка удалена', deleted });
});
```
Для сравнения: `deleteOne()` возвращает только `{ deletedCount: 1 }`.

### 13. Какие методы Mongoose возвращают Query и позволяют строить цепочки?
`find`, `findOne`, `findById`, `findOneAndUpdate`, `findByIdAndUpdate`, `findOneAndDelete`, `findByIdAndDelete`, `updateOne`, `updateMany`, `deleteOne`, `deleteMany`, `countDocuments`, `distinct`.

У Query есть методы для цепочки: `.where()`, `.equals()`, `.gt()/.gte()/.lt()/.lte()`, `.in()`, `.regex()`, `.select()`, `.sort()`, `.skip()`, `.limit()`, `.populate()`, `.lean()`. Запрос выполняется при `await` или `.exec()`. Поиск в проекте (`GET /trips`):
```js
Trip.find()
  .where('status').equals('scheduled')
  .where('price').lte(50)
  .sort({ departureAt: 1 })
  .skip((page - 1) * limit)
  .limit(limit)
  .populate('driver', 'email profile car');
```
Не возвращают Query: `create`, `insertMany`, `aggregate` (возвращает Aggregate), `doc.save()`.

### 14. Как в Mongoose добавить метод экземпляра (instance method) или статический метод модели?
```js
// Метод экземпляра — вызывается у документа: user.comparePassword('123456')
userSchema.methods.comparePassword = function (password) {
  return bcrypt.compare(password, this.passwordHash);   // this = документ
};

// Статический метод — вызывается у модели: User.findByEmail('a@b.c')
userSchema.statics.findByEmail = function (email) {
  return this.findOne({ email: email.toLowerCase() });  // this = модель
};
```
Ещё в проекте: `trip.recalcRating()` (instance) и `Trip.driverRating(driverId)` (static), а также виртуальное поле `user.displayName`.

### 15. Как обеспечить каскадное удаление (при удалении родителя удалить все связанные дочерние документы)?
MongoDB не умеет каскадно удалять сама (нет `ON DELETE CASCADE`), поэтому это делается в приложении:
1. **Middleware (хуки) Mongoose.** Так сделано в `models/Trip.js`:
   ```js
   tripSchema.pre('findOneAndDelete', async function () {
     const trip = await this.model.findOne(this.getFilter());
     if (trip) await Booking.deleteMany({ trip: trip._id });
   });
   ```
   Хук срабатывает на `findByIdAndDelete` / `findOneAndDelete`. Для `deleteOne` / `deleteMany` нужны свои хуки.
2. **Явно в коде роута.** Так сделано при удалении пользователя в `routes/admin.js`: сначала удаляются его брони, потом поездки и брони на них, потом сам пользователь.
3. **Вложенные документы** удаляются вместе с родителем автоматически: удалили поездку, и её `stops` и `reviews` пропали вместе с ней.
4. Для полной надёжности все шаги можно обернуть в **транзакцию** (`session.withTransaction`), но для этого нужен replica set.

### 16. Для каких приложений MongoDB подходит лучше, чем реляционные базы, а для каких хуже? Применительно к курсовому проекту.
**MongoDB лучше подходит**, когда:
- данные естественно иерархичны и читаются целиком (карточка товара, статья с комментариями, профиль);
- структура часто меняется или у разных записей разные поля;
- много чтений, нужна высокая скорость и горизонтальное масштабирование (логи, каталоги, контент, IoT, аналитика событий).

**Реляционные базы лучше**, когда:
- много связей «многие ко многим» и сложных JOIN-отчётов;
- критична строгая целостность и транзакции между многими сущностями (банки, бухгалтерия, склад);
- структура данных стабильна и хорошо нормализуется.

**Для «Попутчика»:** поездка с остановками, условиями, тегами и отзывами хорошо ложится в один документ. Карточка поездки и поиск — самые частые операции, и они выполняются одним запросом без JOIN. Гибкая схема упрощает развитие проекта: можно добавить новые условия поездки или поля машины без миграций. Слабое место — **бронирования и места**: здесь важна целостность (нельзя продать места больше, чем есть). Мы решаем это атомарным `findOneAndUpdate` с условием `seats >= n` и `$inc`, но при оплате или сложных операциях над несколькими коллекциями сразу реляционная БД с транзакциями была бы надёжнее. Разумный вариант для курсового — MongoDB для каталога поездок, профилей и отзывов. Если появятся платежи, их стоит хранить в PostgreSQL или использовать транзакции MongoDB.
